    4. Database and models¶

    SØAD generates models from the connected database. Start with SQL, not handwritten model classes.

    Create and discover tables¶

    Select the application's database in S0ADM's database explorer. Install local authentication first, then execute the tracker schema. The auth user table must exist before the business foreign keys can be created. Run Introspect if the operation has not already refreshed models. Restart after external schema changes if introspection is unavailable.

    The generated name capitalizes the table name: project becomes Project, task becomes Task, and soad_auth_user becomes Soad_auth_user. When a controller has the same name, alias the model:

    from models import Project as ProjectModel

class Project(object):
    pass

    Generated classes and database connections belong to the runtime. Do not check generated models into Git or introduce a separate ORM session.

    CRUD operations¶

    from models import Project as ProjectModel

project = ProjectModel()
project.set("name", "Website launch")
project.set("owner_id", ctx.output["current_user"]["id"])
project.saveIt()

mine = ProjectModel.where("owner_id = ?", ctx.output["current_user"]["id"])
page = mine.orderBy("id DESC").limit(20).offset(0)
one = ProjectModel.first("id = ? AND owner_id = ?",
                         project.getId(), ctx.output["current_user"]["id"])
one.set("name", "Website launch v2")
one.saveIt()

    Use first(condition, values...) for one match; do not call .first() on a LazyList. findById(id) works for a primary key, but private records should be loaded with an ownership condition too. Check for None before modifying a row. delete() deletes a loaded model; the tracker only exposes deletion through guarded POST actions.

    Inputs, search, and relationships¶

    Bind values with ? parameters. Do not interpolate submitted values into SQL. SQL identifiers and sort expressions cannot be value parameters; select them from a fixed allowlist instead.

    sorts = {"newest": "id DESC", "name": "name ASC, id ASC"}
sort = sorts.get(ctx.getParameter("sort"), sorts["newest"])
rows = ProjectModel.where("owner_id = ? AND name LIKE ?",
                          ctx.output["current_user"]["id"], "%launch%")
rows = rows.orderBy(sort).limit(20)

    LIKE treats % and _ as wildcards; decide whether your search UI permits these patterns. Limit page sizes and use stable ordering. The tracker fetches 21 rows and displays 20 to determine whether a next page exists.

    Use explicit foreign keys and indexes. When loading a task, authorize its parent project before reading or changing the task. A valid task ID does not prove the caller may access it.

    IDs, dates, and blobs¶

    Use an auto-increment id for the tutorial and saveIt() for inserts/updates. If you deliberately use a manually assigned string/UUID primary key, use insert() for a new row and saveIt() for an existing row.

    Prefer explicit created_date/updated_date columns if you want application control over timestamps. created_at and updated_at have ActiveJDBC-managed semantics; do not set those reserved timestamps manually.

    The tracker has a separate attachment table to avoid loading blobs in list queries. Uploads are bounded and served through an authorized controller action; they are not public assets.

    Commit, rollback, and migrations¶

    The engine opens a database transaction around dispatch and rendering, commits on success, and rolls back on exceptions. Validate all input before writing. Returning a validation view or calling sendError is not, by itself, an instruction to undo earlier writes. Do not suppress an exception after partial updates and assume they rolled back.

    DDL may commit implicitly in MySQL. Keep migrations separate from web requests, back up first, apply each migration once, and regenerate models afterward. Reverting application source does not revert a database migration.

    For SQL bundles and older IDE schemas, see migrations.
