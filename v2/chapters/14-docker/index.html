    14. Deploy with Docker¶

    Build an application-only image, install its database bundles, and create an application administrator. S0ADM belongs on the development instance.

    Prepare an immutable application release¶

    The tutorial's preparation script creates a fresh release/ containing only its source, built CSS, welcome configuration, security manifest, and SQL bundles. It does not export live users or copy the IDE database.

    For your own app, use S0ADM's release preparation where available or construct an equivalent reviewed build context. The CLI's deploy TARGET_FOLDER only rearranges transaction source; separately include your assets, application libraries, welcome configuration, auth overrides, manifest, and SQL bundles. Do not copy the entire IDE webapp/ directory into an application image.

    flowchart LR
    Source[Reviewed application source and assets] --> Context[Release context]
    Policy[Security plan] --> Manifest[Manifest and auth SQL]
    Manifest --> Context
    Context --> Image[Application image]
    Manifest --> Database[(Production database)]
    Image --> Runtime
    Runtime --> Database

    From the repository root, after building the tracker CSS:

    ./dev.sh build
java -cp 'app/lib/*' org.python.util.jython -B \
  docs/examples/tracker/tools/prepare.py docs/examples/tracker/release
docker build -f app/Dockerfile-base-runtime -t soad-runtime:tracker app
docker build --build-arg BASE_IMAGE=soad-runtime:tracker \
  -t tracker:1.0 docs/examples/tracker/release

    The base uses Java 21 and contains server/ and soad-auth-admin; it omits s0adm/. The application Dockerfile writes webapp/ through /opt/sufia/webapp/, the target of the base's /app/webapp symlink. Keep the base/application versions coupled; use a private registry and immutable tags or digests for your releases.

    Local container rehearsal¶

    The Compose example is deliberately a localhost HTTP rehearsal, with an isolated MySQL database. Supply TRACKER_DB_PASSWORD and TRACKER_DB_ROOT_PASSWORD through your shell's secret input mechanism or an untracked .env file in the example directory. Do not commit that file.

    cd docs/examples/tracker
docker compose up -d db
docker compose exec db mysql --user=root --password --database=tracker \
  -e "source /install/auth-mysql.sql; source /install/tracker.sql;"
docker compose up -d tracker
docker compose exec tracker soad-auth-admin create-admin \
  --app default --email admin@example.com --name "Tracker Administrator" --password-stdin

    Enter the initial application password on stdin when requested by the command. For automated use, pipe a mounted secret file into docker compose exec -T instead. Do not pass a password argument.

    Open http://localhost:8081/_soad/auth/login, then /t/tracker/project. Readiness should return 200:

    curl --fail http://localhost:8081/_soad/auth/health
docker compose logs --tail=100 tracker

    The initial SQL commands are for a fresh database only. For subsequent releases apply reviewed migrations and the release's matching auth metadata bundle. docker compose down preserves the named database volume; adding --volumes would delete it. Local container sessions may be lost on container replacement.

    Production configuration¶

    Use an external or properly managed database, database credentials from your secret manager, a TLS reverse proxy, and a public origin:

    sufia_hostname=https://tracker.example.com
sufia_app_name=Project Tracker
session_cookie_secure=true
session_cookie_samesite=LAX
db_default_driver_class=com.mysql.cj.jdbc.Driver
db_default_url=jdbc:mysql://db.example.internal:3306/tracker?sslMode=VERIFY_IDENTITY

    The database server's certificate chain must be trusted by the JVM for VERIFY_IDENTITY. The local Compose JDBC URL disables TLS solely for its isolated rehearsal network; do not copy it to an untrusted database connection.

    Set database username/password separately, configure SMTP if using recovery emails, and provide writable directories for generated models, logs, upload temporaries, and session storage. Persist business data in the database. The tracker stores attachments there too.

    Upgrade and recover¶

    Back up before migrations, retain the prior image digest, and install matching auth SQL before routing traffic to the new runtime. A checksum mismatch causes 503 readiness/access failure. A changed manifest can also make the old image unready, so coordinate metadata updates and image replacement.

    Use container logs and health checks for diagnostics. The application-only image does not expose S0ADM's log viewer, file editor, or AI service.
