    2. Getting started¶

    By the end of this chapter you will have a development server and a working HTML transaction. Use a disposable local instance for the tutorial.

    Prerequisites¶

    • A checkout of this repository and a Java 21 JDK; set JAVA_HOME to its installation.
    • Docker or another container command compatible with the repository's development script.
    • Access to Gradle dependencies for the initial build.
    • A browser. Python 3 is needed only to build the documentation, not to run transactions.

    From the repository root:

    java -version
./dev.sh build
NERDCTL=docker ./dev.sh startdb
./dev.sh start
./dev.sh status

    Use NERDCTL=nerdctl.lima instead if that is your installed container tool. Open http://localhost:8080/s0adm/. Use the development account configured in dev.sh; obtain its values locally rather than copying development credentials into a deployment. The script currently supplies its own IDE account defaults. Environment variables supplied before dev.sh start do not override every value it sets internally.

    This workflow runs the IDE database in H2 and the application database in MySQL. Use ./dev.sh logs for startup errors and ./dev.sh stop to stop the process. NERDCTL=docker ./dev.sh stopdb stops the local database container.

    If port 8080 is busy, use ./dev.sh start 9090. Check dev.sh for current DB_PORT, DB_NAME, DB_USER, and DB_PW defaults before connecting with a database client. Do not assume the root Compose file is a clean deployment template; use the sanitized examples in this guide.

    Configure the default application¶

    Open System Settings → Applications → the default application. Configure security before expecting application routes to work. For the tracker choose:

    Field Value
    Security profile authenticated
    Authentication mode Application-local identity
    Roles admin (first), member
    Registration invite_only

    Save, follow the one-time setup link, and set an application password. The IDE password is not copied. Keep this account flow separate from the S0ADM login. See authentication for screenshots-free field instructions and the permission grants needed by the full tracker.

    Create your first transaction¶

    In the transaction editor create group web, code hello. Replace the controller:

    from utils import render

class Hello(object):
    ACCESS_POLICY = {"view": "authenticated"}

    def view(self, ctx):
        ctx.output["greeting"] = "Hello from SØAD"
        ctx.go_to = render.as_view(ctx, "hello")

    Save the view as _hello/hello.html within that transaction:

    <!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Hello</title></head>
<body>
  <h1>{{greeting}}</h1>
  <p>Signed in as {{current_user.full_name}}</p>
  <a href="{{logout_url}}">Sign out</a>
</body>
</html>

    Save/compile and open http://localhost:8080/t/web/hello. Sign in with the application account if redirected. You should see “Hello from SØAD” and your name. For a public brochure app, choose public profile/mode and an explicit public policy instead; do not change this protected tutorial to public to bypass setup.

    Common first-run failures¶

    Symptom Check
    No Java or build failure JAVA_HOME, Java version, Gradle dependency access
    Connection refused Process status, port, logs
    Missing models/table Correct application database; run Introspect after DDL
    503 on application route Missing manifest, missing auth SQL, or mismatched checksum
    Redirect repeatedly to login Application account, cookie settings, HTTP vs HTTPS
    404 after creating controller Group/code, capitalized class name, imports and logs

    For plain HTTP development, set session_cookie_secure=false and session_cookie_samesite=LAX for the server process if its active profile requires secure cookies. Restore secure cookies for HTTPS deployment.
